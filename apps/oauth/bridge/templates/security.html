Please test only against your own identities and applications, do not access other people's data, and give us a reasonable time to fix a problem before publishing it.

How this service is built to fail safely

  • It holds no user keys: a compromise cannot sign as you at another Poweur service.
  • Signing keys are stored encrypted and can be rotated; old keys stay published only as long as tokens signed with them are valid.
  • A sign-in can be finished only by the browser that started it, or by one you confirmed with the code it shows.
  • A reused authorization code revokes every token issued from it.

If something goes wrong

  1. Contain. Suspend affected applications (every sign-in to them stops at once), rotate the signing key, or take the service offline. Existing application sessions are the applications' own and are not ended by this service; ID tokens expire within minutes.
  2. Assess from the security log what was affected and since when.
  3. Tell people. Affected users and application developers are told what happened, what it means for them and what to do — within 72 hours of confirming an incident that exposed personal data.
  4. Fix and review, and publish what changed.
